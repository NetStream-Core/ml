# NetStream ML

Датасеты, признаки, модели и оценка для детектора сетевых атак NetStream. Данные берутся из ClickHouse стека `deploy` (размеченные представления `labeled_flows` и `labeled_dns`), обученные модели используются онлайн-детектором.

## Состав

| Путь | Назначение |
|---|---|
| `src/netstream_ml/` | пакет и CLI `netstream-ml` |
| `tests/` | тесты |
| `data/` | выгрузки датасетов (не в git) |
| `artifacts/` | модели и отчёты (не в git) |

## Разработка

Нужны Python 3.12+ и [`uv`](https://docs.astral.sh/uv/).

```bash
uv sync
uv run pytest
just all
```

- `just format` форматирует и правит `ruff`.
- `just lint` запускает `ruff`, проверку форматирования и `mypy --strict`.
- `just test` запускает `pytest`.

## Разбиение на выборки

```bash
uv run netstream-ml data split data/v1 --seed 0 --train 0.6 --val 0.2 --test 0.2
```

Команда читает `labels.parquet`, `flows.parquet` и `dns.parquet` из указанной директории (результат `data export`), добавляет колонку `split` (`train`/`val`/`test`) в `flows.parquet` и `dns.parquet` и пишет `split_manifest.json`.

Единица разбиения — запуск сценария (`run_id`), а не отдельная запись: все записи одного запуска атаки или доброкачественного профиля целиком уходят в одну выборку, чтобы модель не видела один и тот же инцидент и при обучении, и при проверке. Сценарий с тремя и более запусками представлен во всех трёх выборках (наибольший остаток, детерминированный порядок по seed); сценарий с одним-двумя запусками может не попасть в тест или в валидацию — это ограничение малой лаборатории, а не ошибка.

У фонового трафика (`scenario = background`, нет `run_id`) нет привязки к запуску — он идёт постоянно между сценариями. Такие записи группируются по 30-секундным интервалам времени, и каждый интервал целиком уходит в одну выборку. Это уменьшает, но не убирает утечку: фоновый поток, чей интервал съёма пересекает границу 30-секундного окна, может отдать часть своих записей в разные выборки.

Разбиение детерминировано (`--seed`): одинаковый seed на одном датасете даёт одинаковое разбиение, что нужно для воспроизводимости экспериментов. `split_manifest.json` фиксирует seed, доли выборок, разбиение по `run_id` и отчёт о проверке утечек (`check_run_leakage`) для `flows` и `dns`; команда возвращает код выхода `1`, если хоть один `run_id` оказался больше чем в одной выборке.
